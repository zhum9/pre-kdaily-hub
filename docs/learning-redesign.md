# Mario成长岛：一年级学习系统改造

2026-11-01，Asia/Shanghai。家庭起点：孩子一年级；数学、语文出版信息为江苏凤凰教育出版社；英语尚未开课。具体教材版次和学校当前单元待核对。

## 项目现状

本次通过授权 GitHub 连接读取私有仓库 `main` 的 `4914c0855f54c3f2c87e3537db958eb890ecd465`。本地原先为空仓库，27个原始文件逐个通过 Git blob SHA-1 对照后恢复。本地建立导入快照作为差异基线，没有伪造上游提交历史。

网站静态托管，仓库只保留打包后的 React `app.js`、`app.css`、HTML、PWA和图片。没有原始组件源码、服务端或数据库。新增逻辑放入可读、可测试的 `learning/` 模块，通过小范围改动接回原页面。下一步应找回原始 React 源码，逐步替换对打包文件的维护。

原实现的具体问题：

- 数学每轮40道加减算式，用有效签到天数每7天升一档；没有知识点、独立理解或复习证据。文案称数域最高50，实际档位还含70、90、100。
- 使用 `Number(Ke[t])` 批改，存在把空字符串当作0的风险。
- 英语按日期轮换固定主题，句子跟读与识别匹配不能证明真实听说能力。
- `localStorage` 主要保存游戏档案和打卡；课程内容、奖励和渲染耦合在打包文件中。
- 宣城地点列表、侧栏入口、地图弹层、导航协议、相关样式已从运行代码删除。

本次替换数学、英语页面，增加思维探索、成长路线、习惯、家长设置；保留主角、宠物、奖励、日历和原有语文/科普/运动/游戏页面。旧语文模块尚未改造成与实际教材逐课匹配的课程，不能把本次改造理解为全科内容已全部审定。

## 产品结构与教学方式

首页先给数学、英语、思维三张入口，按真实学习记录安排。一次只走一小步，旧资源可选做。游戏奖励代表参与，不证明掌握。

**数学**首批14个主题：5以内数量、10以内数量、比较、分合、10以内加法和减法、生活问题、未知部分、立体图形、11—20十和一、进位加法；下学期方向包括退位减法、100以内数位、平面图形。一次约6题，包含必要基础复习与课堂目标，允许摆实物、看图、使用不同的正确解法。解释连接数的意义与生活情境，不只换数字刷算式。

**英语**首批动物、颜色、食物、学习用品、动作五个情境，每主题4个核心表达和短对话。先听看指认，再听辨回应、尝试跟说，最后用一次真实交流。家长有中文陪伴步骤。听辨图片不预先显示英文答案。设备没有英语声音时明确提示，家长示范记作陪伴练习；不提供虚假的发音能力分数。自然拼读应在听说、音素意识和配套素材完善后逐步加入，本版未冒称完成拼读课程。

**思维/轻奥**提供重复规律、线索排序、不重不漏搭配、有序数路线、天平等量分组。先摆、画、列，再讲理由。搭配不要求先会乘法，天平不套方程。完成后可记录“还想再玩/刚刚好/有点累了”，结合提示和策略长期观察，不输出智商或天赋概率。

**习惯**分为准备文具、学后解释、错题找因、结束整理，由实际行为勾选。选择一个重点也可以，不要求每日全部完成；习惯不折算为知识掌握。

当前包是首批可运行主题，没有覆盖一年级每一课或1—6年级完整题库。先核对孩子课本，再扩大主题和题目形式，比放满虚构关卡更有用。

## 掌握、复习和预习

初始产品规则：最近至多12道不同题目，至少6道独立作答，独立正确率至少80%；正确证据跨至少2天，包含迁移题，并有一次家长在看解析前观察到的自主解释。提示和帮助都是正常学习过程，但不计作独立掌握。

同一道题重复提交不能增加不同题目数量；复习时的新表现会更新该题证据。未稳固主题隔1天建议复习，已有证据的主题隔7天复习。新一轮考虑到期主题、课堂目标和前置薄弱项。这些阈值与题量属于可调整的产品启发式，不是标准化测评或教育部规定。

预习需要家长开启，再逐主题核对前置知识。签到、星星、选择课堂进度都不会自动写入掌握记录；不把一次高分等同于可以跨学期推进。

## 数据设计与迁移

| 数据 | 保存方式 | 关键约束 |
| --- | --- | --- |
| 内容与路线 | 版本化JSON和SHA-256清单 | 稳定知识点ID、题型、前置依赖、学期、来源和核对日期 |
| 学习档案 | IndexedDB `mario-learning` / `state` | 学期、课堂目标、教材备注、预习选择 |
| 作答事件 | 同上 | 唯一事件ID、题目ID、当时题目/答案/提示/解析快照、回应、正误、帮助、解释、版本与日期 |
| 未完成练习 | 同上 | 固定题目、提交结果、当前位置，刷新可续练 |
| 习惯与兴趣 | 同上 | 行为和观察，不作天赋标签 |
| 原有奖励与签到 | 继续使用 `daily-hub-*` localStorage | 不清空，不伪造为学习证据 |
| 完整备份 | 家长下载JSON | 新记录与旧游戏档案一起导出；导入去重合并 |

优先IndexedDB，失败时使用localStorage，再失败时显示临时保存提示。读改写在同一IndexedDB事务内完成，跨标签页通过BroadcastChannel更新，避免覆盖。

导入合并作答、练习、习惯与观察；本机已有配置优先，新设备未配置时使用备份设置。旧游戏数据只恢复缺失键。浏览器存储不等于永久保存：清理数据、换设备前应备份。本版没有云端账号和跨设备同步。

后续若确有多设备需求，再增加家庭身份、服务端数据库和离线同步队列。建议数据表包括 profiles、content_revisions、skills、attempt_events、sessions、habit_events、interest_observations；以事件ID幂等同步，保留内容版本和历史快照。沿用实际托管能力选数据库，不先引入一套没有配置的云服务。

## 动态内容如何更新

动态有两层：每日练习根据学情选题、生成规则变式；课程知识与活动通过版本化内容包更新。后者由应用启动或家长按钮检查本站清单，核对哈希、结构、来源关联、题型和依赖，再启用新版。失败或离线时继续旧版；已开始练习与历史题目保留原快照。

发布流程见README：新增版本化JSON → 核查来源与题解 → `npm run content:build -- catalog-<版本>.json` → 测试 → 随网站发布清单。首次离线安装包变化时更新Service Worker缓存版本和资源列表。

本次完成一次联网查证。系统尚未具备长期自主检索与教师审核发布服务，不会直接把搜索结果或未核实模型回答交给孩子。持续内容生产应走“候选资料 → 原始来源核验 → 原创改写或授权 → 题解审查 → 测试 → 发布”。内容审核与孩子作答数据应相互隔离。

## 下一阶段顺序

1. 核对数学和语文实际目录，用一至两周记录校准起点、解释和复习间隔。
2. 完善数学操作图示、十格框/数轴、读题辅助和错因；补齐实际教材主题。
3. 语文改为课内识字、朗读、复述、阅读理解与课外阅读的分层路线。
4. 英语补经过筛选的原声故事、理解任务与音素/拼读内容，逐步增加表达长度。
5. 思维补开放任务和多种解法的家长观察工具，保留兴趣导向。
6. 按实际需要增加家庭账号、云同步、内容编辑审核和资料候选更新服务。
7. 扩展1—6年级概览时明确区分已实现与规划，逐步推进基础、迁移和拓展。

## 验证范围

引擎检查包含内容哈希、非法依赖、12,000个题目变式、空答案、进位退位约束、去重、掌握门槛、复习、预习、题型覆盖、地图删除、离线资源完整性。

浏览器检查包含旧奖励、提示记录、刷新续练、英语不显示答案、设置、备份下载、手机导航、完整思维练习和离线重载。实际执行结果以测试输出为准；自动检查不替代教师审题和真实家庭试用。
